# Architecture and source decisions

## Target and source evidence

The inspected Zero runs Debian 13 (trixie) ARM64, glibc 2.41, firmware reference 2026-09-29, kernel 6.18.39+rpt-rpi-v8. Its built-in `/dev/fb0` is 320×170 RGB565. Linux exposes a tca8418c keyboard at `/dev/input/event3`, an ES8389Audio ALSA card, and a user `APPLaunch.service`. The `pi` user already belongs to video/input/audio/render groups. No broad permission changes or root application service are installed.

Exact source/documentation commits and the SDK checksum are in `dependencies.lock.json`; matching SDL/libarchive development package URLs/checksums are in `cmake/sdk-packages.lock.json`. Primary references inspected before integration:

- [M5Stack Cardputer Zero](https://docs.m5stack.com/en/CardputerZero)
- [M5Stack usage and physical keyboard guide](https://docs.m5stack.com/en/compute/cardputerzero/usage): the primary 0.2.1 app shortcuts use Ctrl plus an unshifted physical key, avoiding Ctrl combined with the Fn/Sym layers.
- [Official development documentation](https://github.com/CardputerZero/cardputerzero.github.io/blob/main/docs/en/CP0_dev.md), [keyboard map](https://github.com/CardputerZero/cardputerzero.github.io/blob/main/docs/en/CP0_keys.md), [submission rules](https://github.com/CardputerZero/cardputerzero.github.io/blob/main/docs/en/CP0_submit.md)
- [Template](https://github.com/CardputerZero/Template), [AppBuilder](https://github.com/CardputerZero/AppBuilder), [launcher](https://github.com/CardputerZero/launcher)
- [Maintained Frotz](https://gitlab.com/DavidGriffith/frotz), [Z-machine specification](https://www.inform-fiction.org/zmachine/standards/current/index.html)
- [Microsoft design guidance](https://learn.microsoft.com/en-us/windows/apps/design/guidelines-overview) and [keyboard interactions](https://learn.microsoft.com/en-us/windows/apps/develop/input/keyboard-interactions): visible focus, standard navigation, modifier shortcuts and discoverability informed the keyboard UI.

## Integration

The upstream SDL frontend already implements proportional/fixed text, split windows, v6 windows, font3, colours and indexed graphics. Reusing it avoids an incomplete text-only interface and reduces the amount of new VM-facing code. LVGL would add another renderer without replacing the needed Frotz graphical semantics, so the official template's packaging/device conventions are reused while its LVGL dependency is not.

`scripts/prepare_engine.py` applies checked adaptations to a build-directory copy of the pinned Frotz source. Its os_* input, display, file and lifecycle hooks call `src/engine.cpp` directly. Frotz keeps ownership of parsing, opcodes, memory and Quetzal. No game input/output is carried through a text subprocess pipe.

`src/platform.cpp` presents the same 320×170 SDL surface through a resizable desktop SDL window or native framebuffer mapping. Linux evdev events are translated with xkbcommon's US keymap. The display mapping validates size, pitch and pixel channel offsets. `src/model.cpp` owns content identity, scanning, settings, save validation and atomic generations. SDL_mixer keeps sample timing, persistent mute/volume and sound callbacks; silent output is used if a physical sink is unavailable.

The native keyboard translator is shared with the deterministic driver's `evkey CODE VALUE` command. Tests can therefore exercise real Linux keycodes and Ctrl press/release state through xkbcommon without injecting events into the OS or requiring stacked firmware modifiers. Ordinary SDL desktop shortcuts remain supported. Physical accessibility of a chord is checked against the keyboard guide and owner feedback, separately from software event handling.

The library process closes its display before launching the same executable in `--engine` mode, and waits for it. This process boundary resets upstream global state between stories. It does not carry gameplay text. The child returns a small exit/request protocol for library return, application exit or a chosen save. A per-story advisory lock prevents two sessions from updating the same checkpoints concurrently.

## Layout

`src/library_ui.cpp` implements the six-action home, title/synopsis browser and single story page, reusing the platform's menus, wrapped text, focus colours and scrolling messages. `src/catalog.cpp` matches validated release headers against generated offline catalogue data; it never changes save identity or story bytes.

`src/artwork.cpp` shares native-size embedded artwork, menu pictograms and page headers. `src/credits.cpp` adds the home Help hub, About and offline credits, reusing the message reader and Online Library link menu. CMake generates these embedded assets from the canonical SVG's supplied PNGs and the existing author/licence sources. Local PNG/JPEG and indexed Blorb Fspc covers use bounded decoding and thumbnail caching; a procedural landscape supplies a fallback. See [artwork and credits](DESIGN.md).

`src/help.cpp` supplies the shared Controls topic menu and formatted shortcut reference for home Help and in-game Fn+H. It reuses the theme, header, menu routing, font cache and measured text wrapping. Reference rows are paginated as complete units with 14 px key badges and 16 px action text. Opening help changes presentation only; no shortcut row executes the action it describes.

Ordinary v3/v5/v7/v8 stories use the native canvas. V4, recognised Beyond Zork and v6 keep a 640×400 canvas with a stable base font. All supported versions default to Automatic. New sessions use a stable 12 px internal font; reading preferences affect presentation independently. Existing checkpoints retain their recorded VM geometry and fonts. Automatic fits the original canvas for artwork and pointer input, and reuses the Reader for text at line/character pauses, including timed ones. Text is captured before buffering while each character still has its actual logical font/window. This preserves mixed-font prose and excludes graphical-font symbols. Non-status upper text and substantial V6 windows are included; status strips remain in the original view. Large-picture draws and large/full-window clears mark artwork transitions so old prose cannot cover later artwork. Character-menu arrows and timed input retain story semantics; timed text uses PageUp/Down rather than consuming Space/Enter. Tab changes only presentation. All earlier display preferences adopt Automatic once. Explicit choices written with automatic_version=2 persist and override older checkpoint modes. Switching a legacy pixel-view checkpoint to Automatic starts at its latest text without replaying a turn. Reader handles untimed line and character input, so opening key pauses remain readable. The transcript also captures non-V6 upper text below the top two status rows, trimming padding and retaining explicit row changes. Wrap offsets anchor the visible text when the size changes. Outside Automatic, timed input retains the original canvas. Frame + Text Zoom composites a magnified crop inside the scaled V6 window-zero rectangle over a full-screen original layout, using the game's window geometry rather than title-specific coordinates. It activates only at untimed main-window line prompts. Pointer mode and other input modes use the complete layout. `src/view.hpp` shares geometry with pointer mapping. No view change alters VM windows or story bytes. Full playability is assessed separately.

Deletion reuses the scanner without content deduplication to build a hash-bound list of identical story copies and exclusive companions/covers inside the canonical library root. Files referenced by other releases are retained. The confirmed plan is rebuilt before removal, all paths/hashes/writable parents are checked, and the per-story session lock must be available. Only individual regular files are unlinked; there is no recursive deletion. Symlink sidecars, directories, saves, checkpoints, cached metadata and manuals are retained. Partial filesystem failures report the number already removed and refresh the library.

`src/save_ui.cpp` supplies the shared named-save picker used by story pages, the game menu and RESTORE. `src/model.cpp` lists named Quetzal files and checkpoint directories with validation and content fingerprints. Mutations require an unchanged, direct child of that story's `saves` folder. Automatic `resume` is outside this scope. Renames preserve extensions and use Linux `renameat2(RENAME_NOREPLACE)`; unsupported filesystems use an exclusive hard link for regular files or an exclusively reserved empty directory for checkpoints. Existing destinations are never overwritten. Checkpoint deletion verifies a bounded tree without links or special files before removing that explicitly selected directory. No save mutation changes story files.

Separate Blorb packs are indexed once per library scan. Matching embedded code hashes or IFhd release/serial/checksums can associate differently named siblings; an exact same-stem companion takes precedence. Ambiguous candidates are left unattached. Malformed companions do not invalidate the story. Resource-only Blorbs stay out of the game list.

## Resume semantics

Before Frotz decodes a line-read opcode (`0xe4`), the integration checks whether the mode is supported and captures VM Quetzal bytes at the **pre-read program counter**, the stack, screen/window state, RNG and pixel buffer. Operands have not yet been popped from the VM stack. On Continue the private VM state is restored directly and the interpreter executes the original read once, with the saved draft/history. It does not synthesize SAVE/RESTORE commands, run a turn twice, or claim a private boundary snapshot is a portable Quetzal file.

The generation manifest binds VM, screen and versioned frontend components with SHA-256 plus story identity. Writes are fsynced into a temporary generation, renamed as one unit, and the preceding valid generation remains. Portable named saves use the normal Frotz save instruction and a separate atomic destination replacement. Integration tests compare a restored prompt pixel-for-pixel and verify exactly one subsequent turn.

Frontend schema `FZFRONT-8` records whether Automatic was showing the original layout; it retains absolute viewport scale, pan/follow state, reading preference, display mode, Reader page and consumed transcript position. Schemas 2 through 7 remain readable. Initial interpreter clearing cannot overwrite a restored original-layout choice. Interpreter More pauses invalidate the old safe boundary; fresh checkpoints resume at the next complete ordinary line input. A changed preference alters the view; the engine-screen ABI is unchanged. The pinned core's `read` default-argument handling clears an omitted timeout, preventing a previous opcode's third operand from disabling ordinary prompt checkpoints. See the [read opcode specification](https://inform-fiction.org/zmachine/standards/z1point1/sect15.html#read).

V6, timed/character input, active sound, interrupt frames and active transcript/record/replay modes are deliberately excluded from automatic Continue until their full continuation state can be verified. Their native SAVE/RESTORE remains available. Screen sidecars include ABI/schema guards; changes to this private format must bump the schema. Portable saves are checked against release/serial/checksum and complete chunk structure before engine loading.

## Packaging and privacy

The SDK supplies ARM64 target libraries; GCC 13 supplies the cross compiler. The official SDK's pkg-config files mention unshipped static-link development dependencies, so the cross build finds the target shared libraries directly. The package declares Debian runtime dependencies and installs the binary, a uniquely named launcher entry/icon and documentation. There are no maintainer scripts that remove personal data.

The optional Online Library makes bounded HTTPS requests to the fixed eblong.com and ifarchive.org catalogue/story URLs using libcurl. TLS peer/hostname verification stays enabled; redirects are refused. A worker thread reports progress and cancellation while SDL remains on the main thread. It is joined before leaving the transfer screen. Catalogue updates are parsed before atomic cache replacement. Story downloads must match the catalogue full-file MD5 and a valid matching Z-machine header before an atomic, no-overwrite install. No network request runs at startup or during ordinary play. `--online-fixture` requires the deterministic `--drive` test mode; it replaces transport with original local fixtures. See [Online Library](ONLINE_LIBRARY.md). Package/source builders use explicit public file lists, never the local stories, transcripts or credentials. Store screenshots come only from the original CC0 fixture on the actual renderer. The public source archive includes the complete pinned Frotz source and notices, not merely a download URL.

IF Archive uses a bounded libxml2 streaming reader for the official Master-Index.xml. DTDs/entities are refused; only supported Z-code paths outside old/ are retained in a compact JSON cache. libarchive validates ZIP paths, types, encryption, entry count and unpacked sizes before a separate bundle directory is atomically installed with no replacement. Downloaded title/notes metadata is stored by story content identity. See ONLINE_LIBRARY.md for exact limits.
